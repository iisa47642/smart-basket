# Проверка интерфейса

Метод: экспертное прохождение сценариев и автоматизированная проверка браузером. Приглашённых участников, интервью и замеров удовлетворённости не было. Модели пользователей ниже — проектные гипотезы на основе назначения сервиса.

| Модель пользователя | Потребность | Основной сценарий |
|---|---|---|
| Студент | Сравнить небольшую корзину при ограниченном бюджете | Каталог → корзина → один магазин |
| Семья | Быстро подобрать набор и оценить экономию | Наборы → корзина → несколько магазинов |
| Администратор | Обновить цену без повреждения истории | Управление → вход → товар и магазин → цена за дату |

Структура: каталог, корзина, наборы, акции, сравнение товара, история цен, магазины, управление. Город задаётся общим селектором. Публичные разделы не требуют входа. Рабочий интерфейс служит интерактивным прототипом проверяемых сценариев.

Сценарии проверки:
1. Добавить товар, сравнить корзину, изменить количество и убедиться, что старый расчёт скрыт.
2. Сменить город и повторить сравнение.
3. Войти с неверным, затем правильным паролем; проверить понятное сообщение.
4. Добавить историческую цену, исправить её, удалить с подтверждением и выйти.
5. Пройти основные разделы при ширине 390 px; проверить отсутствие горизонтального переполнения всей страницы.

Улучшения: сброс устаревшего расчёта; явное сообщение о сетевой ошибке; подписи полей количества; видимый фокус клавиатуры; ссылка перехода к основному содержимому; подтверждение удаления; сообщения об успешных операциях; перенос элементов корзины на узком экране. Существующие цвета и структура публичных страниц сохранены.

Для полноценной проверки с пользователями подготовлены задания выше. При её проведении отдельно записываются участник под условным кодом, задача, самостоятельное завершение, затруднение и предложенное исправление. Время выполнения, процент успеха и оценки удобства нельзя заполнять без наблюдения.
