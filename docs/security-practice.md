# Как работать с ценами и резервными копиями

Покупателю достаточно открыть каталог. Для просмотра и сравнения цен учётная запись не нужна. Пароль администратора вводят на знакомом HTTPS-адресе в разделе «Управление». На общем компьютере после редактирования нажмите «Выйти». Если в записи неверная дата или сумма, сообщите команде название товара, магазин и дату. В сообщение не включайте пароль, cookie и защитный токен.

Администратор сверяет товар, магазин и дату перед сохранением. Одинаковая дата у одной пары товар–магазин вернёт конфликт 409. Перед удалением проверьте дату в окне подтверждения. При потере доступа обратитесь к владельцу сервера.

Оператор сервера хранит конфигурацию с паролями под правами 600 и выдаёт доступ к резервным копиям отдельно. Для передачи готового архива сначала получите открытый ключ получателя, сверьте полный отпечаток с владельцем по независимому каналу и импортируйте ключ на машине шифрования. Затем выполните:

```sh
scripts/encrypt-backup.sh "$RECIPIENT_FINGERPRINT" "$DUMP" "$DUMP.gpg"
```

Команда сохраняет отдельный зашифрованный файл, оставляя исходную копию на месте. Получатель восстанавливает копию в отдельную пустую учебную БД и проверяет результат до любых действий с рабочей БД:

```bash
set -o pipefail
gpg --decrypt "$DUMP.gpg" | pg_restore --exit-on-error --no-owner -d "$RESTORE_TEST_DB"
```

## Вопросы после инструктажа

1. Как проверить адрес перед вводом пароля?
2. Что сделать после изменения цены на общем компьютере?
3. Как сообщить об ошибке, не раскрывая данные входа?

Для отзыва достаточно назвать роль, непонятный шаг и предложить изменение. Пароли и персональные данные для отзыва не нужны.
